This configuration customizes the `maven-compiler-plugin` to orchestrate compile-time Java Annotation Processing
(JSR-269) for **Lombok**, **MapStruct**, and **Spring Data MongoDB / QueryDSL**.

**Active Annotation Processors**

* **Lombok (`AnnotationProcessorHider`):** Modifies the compile-time Abstract Syntax Tree (AST) to generate getters,
  setters, constructors, and builders directly into the compiled byte-code, reducing boilerplate.
* **MapStruct (`MappingProcessor`):** Scans `@Mapper` interfaces during compilation to generate type-safe,
  high-performance object mapping implementation classes without using runtime reflection.
* **Spring Data Mongo (`MongoAnnotationProcessor`):** Scans `@Document` entities to automatically generate static
  metamodel classes (e.g., generating `QUser` from `User`) for compile-time, type-safe QueryDSL queries.

**Processor Dependencies & Path Isolation**

* **Classpath Isolation:** The `<annotationProcessorPaths>` section tells Maven where to find the processor JARs without
  polluting your project's main runtime classpath.
* **Order & Compatibility:** Including `lombok-mapstruct-binding` solves the order-of-execution problem between Lombok
  and MapStruct. It forces Lombok to run first and generate getter/setter methods *before* MapStruct scans those same
  classes for mapping targets.

**Why This Configuration Is Crucial**

* **Eliminates Race Conditions:** By default, the Java compiler (`javac`) doesn't guarantee the order in which multiple
  annotation processors run. Explicitly configuring the processor paths and the Lombok-MapStruct binding prevents build
  failures where MapStruct fails to find getters/setters generated by Lombok.
* **Zero-Reflection Performance:** Code generation happens entirely at build time. MapStruct and QueryDSL yield direct
  Java code execution, avoiding the heavy memory and latency overhead of runtime reflection.
* **Early Error Detection:** Type-safe query metamodels and mapping implementations cause invalid field names, missing
  getters, or mismatched types to fail immediately at `mvn compile` rather than causing bugs at runtime.
* **Cleaner Build Artifacts:** Keeping build-tool dependencies strictly within `<annotationProcessorPaths>` keeps your
  final application JAR size lean and avoids classpath dependency conflicts in production.
